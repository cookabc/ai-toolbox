# 数据来源与统计口径

| 来源 | 默认路径 | 统计方式 |
| --- | --- | --- |
| ZCode | `~/.zcode/cli/db/db.sqlite` | 只读聚合 `turn_usage`；模型输出来自 `model_usage` 关联的 `step-finish` 记录 |
| Codex | `~/.codex/sessions`、`~/.codex/archived_sessions` | 读取 `token_usage_record.payload.usage`，按响应 ID 去重，模型通过 `turn_context` 关联 |
| Claude Code | `~/.claude/projects` | 读取主会话和 subagents 的 assistant usage，按消息 ID 与请求 ID 去重 |

这些数字是本机已记录用量，不是厂商账单或订阅额度。日志格式不兼容时可能无法读取；自动测试使用合成记录，不能证明所有工具版本均兼容。

「今日」按 macOS 本地日期计算。ZCode 依据回合的 `started_at`，会话日志依据用量记录时间。无有效时间的日志记录只计入累计，并标注部分数据。缺失字段显示「—」，显式零值显示 `0`；今日与累计分别判断字段完整性。

ZCode 的输入构成区分缓存读、缓存创建和非缓存输入。Codex 与 Claude Code 的输入和缓存按来源字段分别显示，不推算非缓存输入，暂不提供回合及工具调用计数。界面最多展示四个模型；ZCode 模型排行仅含完成步骤，可能少于累计输出。

日志按行读取，单行上限 1 MiB，不保留会话正文或工具参数，不跟随符号链接。已识别的超长非用量记录不会触发用量警告；无法确认类型、无法解析的用量记录仍会提示。未变化的会话文件集合复用内存快照；文件变化或跨日后重新扫描。首次扫描和活跃会话刷新耗时取决于历史记录规模。

ZCode 数据库若因 WAL 状态无法直接只读打开，应用会在源数据库没有 WAL 或回滚日志时建立私有临时副本，仅在副本上初始化 SQLite 状态。复制和读取前后检查源文件是否变化；检测到变化就放弃结果，等待重试。副本在源文件未变化时复用，正常释放时清理，不向源数据库写入。

### 可选输出成本

在 `~/.zcode/cli/usage-prices.json` 配置 ZCode 模型的每百万输出 token 美元单价：

```json
{
  "GLM-5.3": { "output": 2.0 },
  "k3": { "output": 1.5 }
}
```

应用汇总所有已配置有效价格的模型完成步骤，不限于界面前四名。未配置价格的模型不计入成本；该值是部分记录的输出成本估算，不代表完整费用。负数或无效价格不参与计算。
